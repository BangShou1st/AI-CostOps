# 04. M1 错误码、幂等与并发约定

## Problem

所有错误使用 `application/problem+json`：

```json
{
  "type": "https://aicostops.dev/problems/resource-not-found",
  "title": "Resource not found",
  "status": 404,
  "detail": "The requested resource was not found.",
  "instance": "/api/v1/projects/99",
  "code": "RESOURCE_NOT_FOUND",
  "traceId": "01J..."
}
```

必需字段为 `type,title,status,detail,instance,code,traceId`；`currentState` 仅在可靠时附加。请求类型不匹配（invalid enum、page/size、path ID）也映射到标准 400 Problem，不泄漏 framework exception。

## M1 status/code matrix

| Condition | HTTP | Code |
|---|---:|---|
| malformed JSON/type/path/query | 400 | `REQUEST_MALFORMED` |
| bean/business validation，含非法 Role/scope pair | 400 | `VALIDATION_FAILED` |
| invalid credentials/access token | 401 | existing auth code |
| stale security version、disabled session | 401 | `AUTH_SESSION_EXPIRED` |
| authenticated but lacks explicit applicable grant | 403 | `FORBIDDEN` |
| nonexistent、cross-org、outside explicit scope | 404 | `RESOURCE_NOT_FOUND` |
| duplicate natural constraint、invalid/repeated lifecycle | 409 | `STATE_CONFLICT` |
| user `expectedVersion` stale | 409 | `STATE_CONFLICT` |
| authentication rate limit | 429 | `AUTH_RATE_LIMITED` |
| invitation delivery unavailable/failure | 503 | `DEPENDENCY_TEMPORARILY_UNAVAILABLE` |

404 是 privacy boundary：同一 endpoint 的 nonexistent、foreign organization、out-of-scope response 必须不可区分。缺少所需 permission 才返回 403。

只有能可靠识别具体 natural constraint 的数据库异常才转换为 409；未知 constraint/SQL failure 不得误报 business conflict 或暴露 SQL detail。

## Optimistic concurrency

`PATCH /users/{id}/status` 必须携带十进制 JSON string：

```json
{"status":"DISABLED","expectedVersion":"4"}
```

`securityVersion` response 和 `expectedVersion` request 都是 string，禁止用 JavaScript number。事务内先锁定 current-org target，再比较 durable `app_user.security_version`，之后才判断 status 是否相同：

- version 不同：409，无 mutation/audit；即使 status 已相同也冲突。
- version 相同且真实变更：status + version bump + audit 同一 MySQL transaction。
- version 相同且 status 相同：返回当前 User，不 bump、不 audit。

客户端遇到 409 必须重新获取资源并提示冲突，不得 blind retry 或自动覆盖。

## Authorization-change transaction

Role assignment/revoke、user disable、project/team membership effective change 必须在同一 durable transaction 内完成业务 mutation、audit 与 target `security_version + 1`。响应只在 commit 后成功。Redis 只做 after-commit best-effort maintenance；MySQL 是 durable authorization truth。

旧 bearer JWT 的 version 校验是 MySQL-first，旧 `sv` 返回 `401 AUTH_SESSION_EXPIRED`，不能被 Redis stale cache 复活。

## Lifecycle and repeat behavior

- Project、Team、CostCenter、ProviderAccount 没有 hard-delete API。
- Project/Team membership DELETE 执行 lifecycle disable，不物理删除。
- Role assignment revoke 是当前 authorization fact 的许可例外；audit 保存历史，重复 revoke 返回 404。
- invalid/repeated master-data or membership transition 返回 409，除非具体 operation 明确定义为 repeat-safe。
- natural assignment/membership/code uniqueness 最终由 MySQL constraint 保证。

## Invitation delivery

`POST /invitations` 不使用通用 Idempotency-Key。existing member/identity conflict 返回 409。delivery boundary 不可用或 delivery exception 返回 503，数据库 transaction 回滚；raw token 永不出现在 API JSON、Problem、audit 或 log。

## Client retry

可在策略明确时 retry：network failure、429/503、幂等 GET。不得 blind retry：400、401 session-expired、403、404、409、password/token validation failure。M1 mutation 没有被文档声明为通用自动重试安全操作。
