## 2. Redis 职责与故障行为

| 场景 | 代码 | Redis down / 超时行为 | 是否可能改变 MySQL 财务真相 | 测试 |
|---|---|---|---|---|
| Refresh Token / 会话 | `RedisRefreshSessionRepository` + `refresh-rotate.lua` | fail-closed 503；轮换 Lua 原子；刷新前重查 MySQL `security_version` | 否 | `RedisRefreshSessionRepositoryIntegrationTest` |
| 登录 / IP 限流 | `RedisRateLimiter` | fail-closed 503 `REDIS_UNAVAILABLE_FOR_AUTH` | 否 | `RedisRateLimiterTest` / `RedisRateLimiterIntegrationTest` |
| 工作台缓存 | `RedisDashboardCacheAdapter` / `WorkbenchQueryService` | cache miss 回源 MySQL；写失败静默 | 否 | `WorkbenchIntegrationTest` |
| Gateway 令牌桶 | `RedisTokenBucketRateLimiter` + `gateway-rate-limit.lua` | 限流开启时 Provider I/O 之前 503 | 否 | `RedisTokenBucketRateLimiterIntegrationTest` / `...FailClosedTest` |
| Gateway 日配额 | `RedisDailyQuotaLimiter` + `gateway-quota.lua` | Provider I/O 之前 503；UTC 日键 + 到午夜的 TTL | 否 | `RedisDailyQuotaLimiterIntegrationTest` |
| Gateway 熔断 | `RedisCircuitBreakerService` | Redis 错误时退化为进程内状态（初态 CLOSED，路由层有界 fail-open），不参与预算/账本 | 否 | `RedisCircuitBreakerServiceTest` / `CircuitBreakerRedisIntegrationTest` |
| IAM 权限上下文缓存 | `RedisAuthorizationContextCache` | 异常回源 MySQL；`security_version` 使旧值不可达 | 否 | `RedisAuthorizationContextCacheIntegrationTest` |

**关键结论**：`gateway/budget/BudgetReservationService` 与 `request/DispatchFenceService` 无 Redis 依赖；预算/账本/关账只由 MySQL 行锁、条件更新与唯一约束裁决。

## 3. 本轮修复

### 3.1 工作台缓存键加入权限指纹（P1）

- 问题：`WorkbenchQueryService` 的 sections 按调用者 ORG 权限裁剪，但缓存键只有 `orgId + period`。同组织低权限成员可命中高权限成员预热的工作台视图，绕过裁剪。
- 修复：缓存键变为 `workbench:{orgId}:{current|periodId}:perm:{sha256(sorted ORG permissions)}`；键内不含用户 ID/邮箱/权限明文。
- 验证：`WorkbenchIntegrationTest.cacheKeyIsScopedByCallerOrgPermissionFingerprint`——高权限用户预热后，低权限成员只看到自己可见的 sections，Redis 中存在两个不同 `:perm:` 键。

### 3.2 Gateway Redis 命令超时（P1）

- 问题：Gateway 未配置 Lettuce 命令超时，Redis 已连接但慢响应/黑洞时，限流、配额、熔断命令可能阻塞到默认 60s。
- 修复：`gateway/src/main/resources/application.yml` 增加 `spring.data.redis.timeout: 500ms` 与 `connect-timeout: 1s`（可用 `SPRING_DATA_REDIS_TIMEOUT` / `SPRING_DATA_REDIS_CONNECT_TIMEOUT` 覆盖）；`compose.v3-operational.yaml` 暴露同名变量。
- 验证：`RedisTokenBucketRateLimiterTimeoutTest` 使用“接受 TCP 但不响应”的本地 ServerSocket + 300ms 命令超时，断言 limiter 在 2s 内返回 `GATEWAY_DEPENDENCY_UNAVAILABLE`。

### 3.3 登录限流 INCR + EXPIRE 原子化（P2）

- 问题：`RedisRateLimiter` 先 `INCR`、再单独 `EXPIRE`，进程中断或 EXPIRE 失败会留下无 TTL 的计数键（键含 windowId，后果是孤儿键/内存泄漏，不是跨窗口限流绕过）。
- 修复：`redis/login-rate-limit.lua` 在单脚本内 `INCR`，并在 `PTTL < 0` 时 `PEXPIRE` 到当前窗口剩余时间；历史无 TTL 键在下一次登录时自愈，不延长进行中的窗口。
- 验证：`RedisRateLimiterIntegrationTest.healsTtlLessKeysLeftByAnInterruptedFirstIncrement` 及原有 429/哈希键/TTL 用例（3/3）。

## 4. 已记录的限制（未改代码）

| 项 | 结论 | 理由 / 后续 |
|---|---|---|
| 熔断 Redis 故障本地降级分支缺专用故障注入测试；`circuit_redis_error` 指标未接线 | **PARTIAL** | Redis 错误时退化为进程内状态是有界 fail-open，不涉及预算/账本；已在此登记，后续可在 `RedisCircuitBreakerService` 的三个 `onErrorResume` 增加指标与单测 |
| 配额/令牌桶/登录窗口使用应用 Clock，未用 Redis `TIME` | **可接受** | 单实例按 UTC 计算；多实例依赖 NTP；午夜/窗口边界最多短暂出现双键，属边界语义。若业务要求严格单日上限，再单独评审 Lua + Redis TIME 改造（会改键构造） |
| 令牌桶状态固定 `SETEX 60s` | **可接受（默认配置）** | 默认 capacity=60、refill=1/s，恰好 60s；`capacity > 60 × refill` 的非默认配置会因状态过期而提前满桶。已在 `GatewayProperties.validate` 之外登记，若启用大容量桶需单独调整 TTL |
| 刷新会话 create/revoke 由多条 Redis 命令组成 | **已知限制** | 崩溃可能留下不可达且无 TTL 的 refresh hash；登录返回 503，客户端拿不到凭据。生产迁移禁止 flushAll；如需清理，按前缀 SCAN + `TTL=-1` 一次性处理 |
| 工作台缓存无写后失效、无 single-flight | **可接受一致性等级** | 只读聚合；MySQL 为真相；最长 60s 陈旧窗口；财务写操作不经过工作台缓存回写；缓存故障按 miss 回源。若出现真实高并发 miss 证据，再评估 single-flight |

## 6. 结论

Redis 在所有审查场景中都不是财务真相：预算、账本、关账由 MySQL 裁决；Redis 故障按各入口的既有约定 fail-closed 或回源。本轮修复了同租户跨权限缓存泄露、Gateway Redis 慢响应阻塞与登录限流 TTL 崩溃窗口；其余边界已按 `PARTIAL` / 可接受语义登记，未以“线上已发生”或“已验证生产”措辞夸大。
